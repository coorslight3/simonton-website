# Working on this project locally (with Claude Code)

This is for editing the site on your own computer, with full preview and Claude Code.
If you would rather make small text changes in a web browser and skip all setup, read
`EDITING.md` instead. Both routes publish the same way.

## 1. Accept the repo invite

Check your email or <https://github.com/notifications> for an invitation to
`coorslight3/simonton-website`. Accept it. You now have write access.

## 2. Install what you need

- **Git** (macOS: it comes with Xcode command line tools, `xcode-select --install`)
- **Python 3** (macOS ships it; check with `python3 --version`)
- **Node** (only used to read `site/team-data.js`). If you do not want to install it, this
  repo ships a stand-in for macOS: run `PATH="$PWD/tools/bin:$PATH" python3 build_team.py`.
- **Claude Code**: <https://claude.com/claude-code>

## 3. Get the code

```sh
git clone https://github.com/coorslight3/simonton-website.git
cd simonton-website
```

If git asks for a password, use the GitHub CLI instead: `gh auth login`, then clone again.

## 4. Build and look at it

```sh
python3 build_team.py     # regenerates the pages from the data files
python3 serve.py          # preview at http://localhost:8123
```

Open <http://localhost:8123>. `serve.py` never caches, but add `?r=1` to a URL if a page
looks stale anyway.

## 5. Point Claude Code at it

```sh
cd simonton-website
claude
```

It reads `CLAUDE.md` in this folder automatically, which tells it the build rules, the
black and white palette, the "use the client's wording verbatim" rule and the no em dashes
rule. Project history, past decisions and the open items list are in `HANDOFF.md`, which is kept
out of this public repo. Ask Robert for a copy before making content decisions.

## 6. Publishing a change

```sh
git pull                  # ALWAYS do this first
# ... make your change, run build_team.py, check it in the browser ...
git add -A
git commit -m "What you changed"
git push
```

The push triggers a build check on GitHub, and the live site updates about a minute later.

## Working on this at the same time as someone else

- **`git pull` before you start.** This avoids almost every conflict.
- **Commit and push in small pieces** rather than one big batch at the end.
- If git refuses your push because the other person pushed first, run `git pull` and try
  again. If it reports a conflict in a file, that means you both edited the same lines;
  git marks them and you pick which version is right.
- Nothing is ever lost. Every version is kept and any change can be reverted.
- If you would rather have changes reviewed before they go live, work on a branch and open
  a pull request instead of pushing to `main`.

## The one thing that will bite you

**Do not edit any `.html` file in `site/` except `site/index.html` and
`site/coverage-map.html`.** Everything else in there is generated by `build_team.py` and
your edit will be erased on the next build. The table in `EDITING.md` says which source
file to edit instead. Those generated pages are not even tracked in git, so if you edit one
you will notice git ignoring it.
